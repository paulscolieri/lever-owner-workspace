# 03. Process inventory and roadmap

Goal: every process on one page, ranked, so you know what to tackle first.

```
Help me build knowledge/roadmap.md, a list of every recurring process in the business.

1. First, read knowledge/ so you know what I've already documented.
2. Then walk me through the business area by area (sales and quoting, scheduling, delivering the work, customer service, billing and collections, purchasing and vendors, hiring and team, reporting, admin). For each area, ask what recurring work happens and who does it today.
3. For each process, fill in the table in knowledge/roadmap.md: how often it happens, hours per month, who does it, what software it touches, how painful it is (1-5), and how rules-based vs. judgment-heavy it is.
4. When we're done, rank them by (hours x pain) and tell me which 2-3 are the best first candidates and why.

One area at a time. Don't fill in numbers I haven't given you; ask.
```

Follow-up, once the list is done:

```
Using knowledge/roadmap.md, draft a 12-18 month rollout plan: which process in which quarter, what each one would need (software connections, data, people), and what we'd measure to know it's working. Write it under "Rollout plan" in the same file. Keep it to one page.
```
